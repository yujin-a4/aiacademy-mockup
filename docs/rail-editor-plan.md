## 0. 이 문서를 처음 읽는 사람에게

### 0-1. 무엇을 하려는 일인가

콘텐츠팀은 지금 스캐폴딩 레일을 **구글 시트**에서 짠다. 그런데

- 시트에 **상호작용 열이 없어서** `common`·`yun_daeun` 레일은 화면 동작을 지정하지 못한다
  (**경고 40건 중 39건이 이 문제**)
- 시트를 고쳐도 **화면에서 어떻게 도는지 보려면** 동기화를 돌리고 앱을 열어야 한다
- 순서를 바꿔보는 실험은 사실상 불가능하다

그래서 **DB를 직접 편집하는 화면**을 만든다. 단, 지금 돌아가는 레일은 절대 안 건드린다.

### 0-2. 용어

| 말 | 뜻 |
|---|---|
| **레일** | 수업 한 바퀴의 단계 순서. `type_rails` 에 있다 |
| **정본 레일** | 지금 학생 화면이 보는 것. `draft_id is null` 인 행 |
| **드래프트** | 콘텐츠팀이 편집 중인 **사본**. `draft_id = 'kim-0729'` 같은 값이 붙은 행. **빈 상태가 아니라 현재 정본 레일을 통째로 복사해서 시작한다** (§2-1) |
| **변종** | 단계를 화면에서 어떻게 시킬지. `step_variants` **20종**. 편집기의 드롭다운 |
| **승격** | 드래프트를 정본으로 올리는 것. `draft_id` 를 null 로 하고 `version+1` 로 **새로 INSERT** |
| **네임스페이스** | 드래프트를 서로 격리하는 이름. `draft_id` 값 하나가 곧 한 벌의 레일 |

## 1. 절대 규칙 — 분리

이 계획의 최우선 요구다. **약속이 아니라 구조로 막는다.**

| # | 규칙 | 무엇으로 보장하나 |
|---|---|---|
| R1 | 정본 650행에 **UPDATE·DELETE 를 하지 않는다** | 편집기 경로에 UPDATE/DELETE 코드를 만들지 않음 + DB 권한 |
| R2 | 학생 화면은 드래프트를 **볼 수 없다** | 뷰에 `where draft_id is null` — 코드가 아니라 뷰가 막는다 |
| R3 | 문항·지문·보기는 **읽기만** | 편집기는 `questions`·`passages` 계열에 쓰기 코드가 없다 |
| R4 | 드래프트는 **정본 네임스페이스에 행을 만들 수 없다** | 서버 라우트가 `draft_id` null 을 거부 |
| R5 | 되돌리기는 항상 **삭제 한 줄** | 드래프트는 `delete where draft_id=$1`, 승격분은 그 `version` 삭제 |

**R3 이 중요하다.** 편집기는 **레일(수업 순서)만** 만진다. 교재에서 뽑아 넣은
문항 104개 · 보기 410개 · 지문 17개 는 손도 대지 않는다.

## 2. 콘텐츠팀은 0에서 시작하지 않는다

**이걸 먼저 못 박아둔다.** 드래프트는 빈 표가 아니다.

"새 드래프트 만들기" 를 누르면 **지금 돌아가는 레일이 그대로 복사된다.** 예를 들어
`P1-PHOTO-SUBJECT × lee_doyun` 은 지금 7단계인데(실측):

```
1. S1 핵심 관찰 영역 잡기   [S1-mark]    필기 인식   재생 없음
2. S3 사진 유형별 표현 코칭  [S3-next]    AI 진행     재생 없음
3. 선택지 A 청취 + S6/S5    [S6-choice]  선택 응답   A 음원만 재생
4. 선택지 B 청취 + S6/S5    [S6-choice]  선택 응답   B 음원만 재생
5. 선택지 C 청취 + S6/S5    [S6-choice]  선택 응답   C 음원만 재생
6. 선택지 D 청취 + S6/S5    [S6-choice]  선택 응답   D 음원만 재생
7. S7 표현 정리             [S7-next]    AI 진행     재생 없음
```

편집기를 열면 **이 7단계가 그대로 떠 있다.** 거기서 6번을 지우거나 3번을 앞으로 당긴다.

그리고 **문항·지문은 복사조차 하지 않는다.** 드래프트도 원본을 그대로 본다 —
미리보기를 열면 사진·보기·음원·정답이 전부 지금 것이다. 바뀌는 건 **"어떤 순서로 무엇을 시키느냐"** 뿐이다.

| | 드래프트에서 |
|---|---|
| 레일(수업 순서) | 복사본을 만들어 편집 |
| 문항 104 · 보기 410 · 지문 17 | **복사 안 함. 원본 그대로 읽음** |

미리보기는 **드래프트 행만** 본다 — 정본과 섞이지 않는다. 그래서 복사가 **완전해야** 한다
(일부만 복사하면 그만큼만 도는 수업이 된다).

## 2-2. 핵심 설계 결정 — 네임스페이스를 어디에 둘까

### 채택: `type_rails.draft_id text default null` 컬럼 신설

```
정본      draft_id = null          ← 지금 650행. default 라 한 글자도 안 바뀐다
드래프트  draft_id = 'kim-0729'    ← 새로 들어오는 행
```

**왜 이게 맞나**

1. **기존 행이 안 바뀐다.** `default null` 이라 `alter table` 만으로 650행이 그대로 정본이 된다
2. **뷰 한 줄로 완전 차단.** `where draft_id is null` 을 뷰에 넣으면 학생 화면은 **드래프트를 볼 방법이 없다.** 화면 코드를 안 믿어도 된다
3. **축이 안 섞인다.** `instructor_code` 는 계속 `lee_doyun` 이다 — 어느 강사의 레일을 고치는 중인지가 유지된다

### 기각: `instructor_code` 에 `sandbox_a` 를 넣는 안

처음 검토했으나 **함정이 두 개**라 버린다.

- 🔴 **강사 목소리가 바뀐다.** `tutorAgentFor()` 는 매칭이 안 되면 조용히 기본 에이전트로 떨어진다
  (`instructorData.ts:76`). `sandbox_a` 로 열면 이도윤 목소리가 아닌 게 나온다 —
  **레일을 평가하러 열었는데 강사가 다른 사람이 된다**
- 🔴 **무엇을 고치는 중인지 사라진다.** `sandbox_a` 는 어느 강사 레일에서 갈라져 나온 건지 모른다

### 쓰기는 반드시 서버 라우트를 거친다

`0016:139` 가 브라우저(anon 키)의 `type_rails` 쓰기를 이미 막아놨다. 그래서 편집기는
**`/api/rail-draft` 서버 라우트**를 통해서만 쓴다. 이건 제약이 아니라 **이득**이다 —
쓰기 길목이 하나뿐이라 거기서 R4(정본 네임스페이스 금지)를 강제할 수 있다.

### ✅ STEP 0 — 뷰의 버전 해석 버그 수정 · **완료 (2026-07-29, `0020`)**

**실측한 문제** — 뷰의 현재 정의:

```sql
SELECT DISTINCT ON (tr.question_type_id, tr.instructor_code, tr.step_order) ...
```

### ✅ STEP 1 — 분리 장치 · **완료 (2026-07-29, `0021`+`0022`)**

> **왜:** 편집기를 만들기 전에 **격리 벽**부터 세운다. 벽이 없으면 첫 INSERT 가 사고다.

**작업**

- [ ] `0021_rail_drafts.sql`
  - `alter table type_rails add column draft_id text default null`
  - `create index type_rails_draft_idx on type_rails (draft_id, question_type_id, instructor_code, step_order)`
  - **뷰에 `where draft_id is null` 추가** (R2)
  - 드래프트 메타 표 신설 — 목록·소유자·설명이 필요하다

```sql
create table rail_drafts (
  draft_id     text primary key,           -- 'kim-0729' 같은 사람이 읽는 이름
  title        text not null,
  base_instructor text not null,           -- 어느 강사 레일에서 갈라졌나
  note         text,
  created_by   text,
  created_at   timestamptz not null default now(),
  promoted_at  timestamptz                 -- 승격되면 기록. null이면 작업 중
);
```

- [x] 권한 — `type_rails` 는 이미 브라우저 쓰기가 막혀 있다(`0016:139`). **그대로 둔다.**
      `rail_drafts` 도 같은 방침으로 revoke

**🔴 작업 중 발견 — 유니크 제약이 격리를 막고 있었다 (`0022`)**

`type_rails` 의 유니크 제약에 `draft_id` 가 빠져 있었다:

```
UNIQUE (question_type_id, instructor_code, version, step_order)
```

드래프트는 **정본을 통째로 복사해서 시작**하므로 당연히 같은 좌표를 갖는다.
→ `duplicate key value violates unique constraint` 로 **한 행도 못 넣는다.**
격리 설계의 전제가 깨지는 지점이라 `0022` 로 고쳤다.

```sql
unique nulls not distinct (draft_id, question_type_id, instructor_code, version, step_order)
```

**`NULLS NOT DISTINCT` 가 핵심이다.** 기본 동작(`NULLS DISTINCT`)으로 걸면 `draft_id` 가 null 인
행끼리 서로 다르다고 보아 **정본의 중복이 허용돼 버린다** — 지금 있는 보호가 조용히 사라진다.
PostgreSQL 15+ 문법이고 현재 17.6 이라 사용 가능.

**완료 조건 — 전부 충족**

| 조건 | 결과 |
|---|---|
| 화면 동작이 수정 전과 동일 | ✅ `v_lecture_program` 1733행 md5 `7e93cdee…` **0020 이후 계속 동일** |
| 정본 650행 불변 | ✅ md5 `c9c3d11c…` 동일 |
| 드래프트가 학생 화면에 **안 나온다** | ✅ 정본과 **같은 version(2)** 으로 드래프트 3행 투입 → 뷰 해시 **미동 없음** |
| 드래프트는 직접 조회하면 존재 | ✅ 3행 |
| **정본 중복 보호 유지** (0022 의 위험) | ✅ 정본 좌표 중복 삽입 시도 → 차단됨 |
| 드래프트 네임스페이스 내 유일성 | ✅ 같은 드래프트 내 중복 삽입 → 차단됨 |

| 빌드 | ✅ exit 0 |

### ✅ STEP 3.7 — 시트 입력 점검 후속 · **완료 (2026-07-30)**

> **왜:** STEP 3.6 직후 시트를 실측했더니, 폼은 맞는데 **적어둔 값의 절반이 화면에 안 닿았다.**

기본값 6종 중 3종이 사전 밖이라 무음이었고, `선택지 전체 재생`은 전체 음원으로 새고 있었다.

| 시트 문구 | 전 | 후 |
|---|---|---|
| 정답 선택지 재생 | 무음+경고 | 정답 보기 1개 재생 (**문항 DB 정답 표시로 대상 판별**) |
| 오답 선택지 재생 | 무음+경고 | 오답 보기 전부 이어서 |
| 질문 다시 재생 | 무음+경고 | 발화 문장 재생 |
| 선택지 전체 재생 | 전체 음원(질문까지) | 보기만 이어서 |
| 질문과 선택지 전체 재생 | 발화만(보기 누락) | **`mix` 신설** — 발화 + 보기 이어서 |

핵심은 보기를 `A~D` 로 적지 않고 **"정답/오답"으로 지목**할 수 있게 한 것 — 문항이 바뀌어도
시트를 고칠 필요가 없다. `mix` 는 문장 id 를 명시적으로 실어 아이템 병합(`fromItems.remapAudio`)
에서 어긋나지 않게 했다(Part2 는 강의당 아이템 3개라 발화가 섞일 수 있었다).

**1-b) "정답 선택지"로 지목한 turn 의 상호작용** (`readCorrectLabel`)
SC1·SC2 의 S5 가 `정답 고르기`로 떨어져 **이미 들려준 답을 다시 고르라고** 시키고 있었다.
음원 지시가 정답 보기를 지목하면 그 보기 하나의 맞다/아니다 2지선다로 처리한다.
`정답 근거 연결`처럼 *선택지/보기* 를 지목하지 않는 문구에는 발동하지 않는다(SC5 오작동 방지).

**2) 문항별 반복** (시트 G열 `문항별 반복` + `fromSteps.expandPerQuestion`)

수업이 끝나고 있었다.** 시트에는 `예` 표시만 하고 문항 수는 화면이 센다 → Part7 에 5문항
지문이 와도 시트 수정 없이 5바퀴 돈다.
**연속된** `예` 단계는 한 묶음으로 반복한다 — `Q1(S5→S6) → Q2(S5→S6) → …`.
단계별로 펼치면 S5 세 번 → S6 세 번이 되어 학생이 문항을 오간다.
실측: 3문항 아이템에서 레일 6단계 → **10턴**, 경고 0.

**3) 매핑표 안전장치** (`api/sandbox` 검증 + 동기화 결과)

  "고쳤는데 안 바뀐다"의 원인). SC8·9 에 있던 괄호 안내문은 도움말로 옮겼다
- 파트가 1~7 숫자가 아니면 에러

## 4. 사람이 정해야 진행되는 것

| # | 결정 | 누가 | 막는 단계 |

| **D-A** | **레일 정본을 시트에서 DB로 옮길 것인가.** 옮기면 콘텐츠팀 작업 방식이 시트→편집기로 바뀐다. 안 옮기면 이중 입력이 되고 시트 동기화가 툴 작업물을 덮는다 | 기획+콘텐츠 | **STEP 5** (STEP 0~4 는 안 막는다) |
