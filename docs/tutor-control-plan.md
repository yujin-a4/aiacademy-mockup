# AI 강사 통제 계획 — LLM 가두리

> **이 문서는 진행 중인 작업의 이어가기 지점이다.** "오늘 할 거 뭐야?" 로 시작하면 §5(다음 할 일)부터 보면 된다.
> 최종 갱신 2026-07-30 · 브랜치 `feat/rail-editor-sandbox`

## 1. 문제 — 왜 이 작업을 하나

수업을 실제로 돌려보니 강사(에이전트)가 **화면과 어긋나는 말**을 계속 했다. 실측 사례:

| 실제로 나온 말 | 무엇이 어긋났나 |
|---|---|
| "에이 비 씨 디 중에 뭐 같아 말해봐" (S1 첫 턴) | 보기 음원을 **틀기도 전** |
| "사진에서 가장 눈에 띄는 핵심 **단어**를 골라봐" | 사진에는 단어가 없다 |
| "C와 D 중 오답인 보기를 골라봐" | 화면에 뜬 선택지는 **A·B** |
| "지금 **들은** 보기들 중에서 골라" | 음원은 그 말 **뒤에** 재생된다 |
| "다른 보기 하나 골라봐" | 화면이 이미 잠겨 **누를 수 없었다** |

원인은 프롬프트 품질이 아니라 **구조**였다. 프롬프트로 "하지 마라"를 쓰는 건 가장 약한 통제다.

## 2. 통제의 5개 층 (업계 표준 대비 우리 위치)

조사 결과, 우리가 하려는 것에는 이미 이름이 붙어 있다. 위쪽이 강한 통제다.

| 층 | 업계 이름 / 선례 | 우리 상태 |
|---|---|---|
| 흐름 소유 | FSM·graph (LangGraph, Pipecat Flows) | ✅ 레일 = DB 상태 기계 |
| **정보 차단** | node-scoped context, context engineering | ✅ **A단계 게이트** (§3) |
| 전이 통제 | transition guard | ✅ `next_step` 거절·속도 가드 |
| **결정론 생성** | slot filling / templating<br>(AutoTutor+LLM: "LLM이 FSM의 상태 공간을 채운다") | 🟡 **B단계 — 절반** (§5) |
| 출력 검증 | guardrails (NeMo Guardrails, Guardrails AI) | ❌ 없음 |
| 관측 | guardrail metrics (Khanmigo: "학생이 답하기 전에 답을 알려준 횟수") | ❌ 콘솔 로그뿐 |

참고 — [AutoTutor meets LLMs (arXiv 2402.09216)](https://arxiv.org/abs/2402.09216) ·
[Pipecat](https://github.com/pipecat-ai/pipecat) ·
[Khan Academy: Building a Better AI Tutor](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/) ·
[FlowAgent (arXiv 2502.14345)](https://arxiv.org/pdf/2502.14345)

> FlowAgent 논문이 짚는 대가: 규칙 기반은 준수율이 높지만 **가드를 늘릴수록 복잡도가 급증**한다.
> 그래서 가드를 무한정 더하는 대신 **LLM에게 맡길 자리를 줄이는 쪽**(B단계)이 맞다.

## 3. 끝난 것 (2026-07-30)

### A단계 — 단계별 정보 게이트 `src/data/typeLearning/stageGate.ts`

**모르면 말할 수 없다.** 그 단계에서 필요 없는 사실은 아예 주지 않는다.

| 등급 | 단계 | 에이전트가 아는 것 |
|---|---|---|
| 1 clue | S1~S4 | 사진·지문만. 보기 ✗ 정답 ✗ |
| 2 solve | 학생 풀이·전체 풀기·정답 고르기 | 보기 ○ 정답 ✗ |
| 3 answer | S5 | 정답 + 근거 |
| 4 review | S6·S7 | 오답 이유까지 |

- 단계 이름에서 **S코드를 전부** 뽑아 최댓값으로 판정 (정본은 `Q1-S5 + 쉐도잉 + S6` 처럼 복합)
- 같은 아이템 안에서는 **한 번 오르면 안 내려간다** (대화 컨텍스트는 회수 불가)
- **아이템이 바뀌면 1로 리셋** — Part1은 사진 3장이 아이템 3개라, 리셋이 없으면 2번째 사진의 S1에서 이미 정답을 안다
- 통로 **둘 다** 적용: 에이전트 귓속말(`buildLessonFacts`) + 문구 생성(`factsOf`, 아이템×등급으로 나눠 호출)
- 예외: 표시 판정(`api/mark-check`)은 정답을 알아야 채점되므로 항상 전체를 준다(학생에게 노출 안 됨)

### 진행(페이싱) 통제 `TypeLessonPlayer.tsx`

- **응답 게이트**: 학생이 할 일이 있는 턴은 응답 없이 못 넘어간다. 최대 2회 재질문(간격 6초, 포기 전 8초) 후 답·근거를 짚어주고 진행
- **빈 응답 무시**: STT가 침묵을 `"..."` 로 전사해 보내는 것을 응답으로 세던 버그
- **반응 먼저**: 답이 와도 강사가 그 내용에 반응하기 전에는 진행 보류
- **자동 전진**: `AI 진행` 턴은 화면이 넘긴다(발화·음원 종료 후 0.7초)
- **몰아 넘기기 차단**: 전진 직후 1.2초 재호출 무시, `AI 진행` 턴은 5초간 에이전트 진행 거절
- **음원 타이밍**: 지시문에 "아직 안 들려줬다"를 싣고, 재생이 끝나면 `[진행] 음원 재생이 끝났다` 신호

### 화면·문구 버그

- **정답 클릭 불가** — `focusQ`가 문항 1개짜리 아이템에서 `undefined`라 보기가 영영 선택 불가였다
- **오답 재시도** — 맞혔을 때만 채점. 오답은 그 보기만 빨갛게, 정답은 공개 안 함. 전달 키에 보기를 넣어 재시도가 매번 강사에게 감
- **문구 회수 (B단계 착수분)** — 판정형(`맞아요/아니에요`)·오답 고르기는 코드가 문구를 만든다(`fixedPrompt`)
- **자료 종류 명시** — 사진 문항에 "단어를 고르라"고 하던 원인 줄 차단

## 5. 다음 할 일 (우선순위 순)

### ① B단계 마무리 — 지시 문구를 LLM에서 회수  ★다음 작업

문장 골격은 코드가, `{대상}`만 LLM이 채운다. **DB·시트 변경 없음.**

| 턴 종류 | 문구 출처 |
|---|---|
| 판정형(맞아요/아니에요) | ✅ 코드 |
| 오답 고르기 | ✅ 코드 |
| **정답 고르기(pickAnswer)** | ❌ LLM ← 남음 |
| **표시하기(mark)** | ❌ LLM ← "사진에서 핵심 단어를 골라봐"의 원인 |
| **전체 풀기·주관식** | ❌ LLM ← 남음 |

작업 순서: `materialOf(turn, lesson)`(사진/지문/표/문장) → `ACTION_TEMPLATE[kind][material]` 사전 →
`rail-prompts`가 문장 대신 **대상 어구만**(20자) 생성 → `fixedPrompt`로 고정 → 배너·directive 동일 문자열 사용.

### ② 출력 검증기 (반나절)

음성은 막을 수 없으니 사후 감지 + 교정이 현실적인 최선.

## 7. 대본 밖 자유 질문 — 지금 어디까지 되나 (2026-08-13)

학생이 **'질문 있어요' 를 누르지 않고 그냥 물어봐도** 강사가 답하고 스스로 대본으로 돌아온다.
겉으로는 모드 전환이 없지만, 속으로는 버튼 모드와 **같은 `asking` 을 켠다** — 진행 게이트
(자동 전진 차단)가 거기 걸려 있어서 따로 만들면 답하는 동안 화면이 다음 단계로 넘어간다.

### 들어온 말을 무엇으로 볼 것인가 (`onSend` 의 순서)

| 순서 | 자리 | 판정 | 위험 |
|---|---|---|---|
| 1 | 질문 모드(버튼) | 질문 | 없음 |
| 2 | 주관식 턴, 아직 답 안 함 | 낱말 겹치면 답 · 아니면 LLM 이 `O`/`X`/`Q` | 낮음 |
| 3 | 음원 턴 + "다시 들려주세요" | 부탁 | 없음 |
| 4 | **선택지 턴, 아직 안 고름** | 글자·번호·O/X 로 맞으면 그 선택지 | 낮음 |
| 5 | 그 외 | 질문 | 없음 |

2번의 `Q` 갈래는 **기대 답과 낱말이 하나도 안 겹칠 때만** 닿는다(겹치면 그 위에서 정답으로
끝난다). 그래서 진짜 답이 질문으로 오해될 자리가 애초에 없다. 판정 실패·타임아웃(2.5초)이면
예전대로 `O`(맞음)로 떨어진다.

### 🔴 알려진 한계 — 선택지 턴의 **동의어**를 못 잡는다

4번은 **글자 대조**다. 뜻이 같아도 글자가 안 겹치면 못 알아본다.

```
"사람과 사물 중에서 무엇을 먼저 봐야 할까요?"   선택지 [사람 / 사물]
  "사람" ✓   "1" ✓   "2번" ✓          ← 잡는다
  "인물" ✗   "사람이요 아마도" △        ← 못 잡는다 → 질문으로 간다
```

**갇히지는 않는다.** 질문으로 가면 강사가 한 번 답하고 `자, 다시 볼게요. {원래 물음}` 으로
돌아오며 버튼이 다시 뜬다. 다만 학생이 답을 한 것인데 설명을 듣게 되므로 어색하다.

왜 LLM 판정을 안 붙였나 — 주관식(2번)과 달리 선택지 턴은 **매 입력마다** 왕복이 생긴다.
2.5초 침묵이 붙고, 오분류하면 엉뚱한 선택지를 고른 것이 되어 채점이 틀어진다. 버튼이 바로 옆에
있는 자리라 값을 치를 만한가가 분명치 않아 보류했다.

붙인다면 이렇게: 낱말 대조가 실패했을 때만, 판정기에 선택지 목록을 주고 "몇 번인가 / 질문인가"를
한 번에 묻는다(주관식의 `judge` 왕복과 같은 자리·같은 타임아웃). 실패하면 지금처럼 질문으로.

### 되묻기 금지

답 끝에 물음표를 달면 학생이 거기 대답하고, 그 대답이 또 질문으로 들어와 **대본으로 영영
못 돌아온다**(실측: 여덟 번을 주고받았다). `askTutor` 프롬프트에 "되묻지 마라"를 못 박았다.
