# 리포트 화면 요구사항 — 개발사 전달용

> 경로: `/status` → **리포트** 탭 · 대상 MVP1
> 작성 2026-08-03 · 확정 2026-08-04

**갱신 주기:** 전부 **실시간**. 화면에 들어올 때마다 DB에서 다시 계산함. 집계 배치·생성 크론 없음.
문제를 풀고 리포트에 들어오면 바로 반영됨.
→ 예외는 ④의 **처방 대상 파트 선정** 하나뿐 (주 1회 고정, 사유는 ④ 참고)

**블록 구성:** ①② 한 줄, ③④ 한 줄. **③과 ④는 높이를 맞춤**(처방 항목 수에 따라 한쪽만 길어지지 않게).

---

## ① (누적) 전체 정답률

총 풀이 문제 수 대비 정답률

- 보조 문구: `목표 n점, 시험 D-n, 누적 n문제 기준`
- 데이터 없으면 `-` 으로 표시, 임의 값을 넣지 않음
- **실시간, 전체 기간 누적**

## ② 주간 풀이 문제 수, 총 학습일 수, 파트별 정답률 (LC/RC)

- 주간 풀이 = 최근 7일간 푼 문제 수 — **실시간·주간**
- 총 학습일 = '학습'을 진행한 일의 합계 — **실시간·누적**
- LC 정답률 = Part 1~4 — **실시간·누적**
- RC 정답률 = Part 5~7 — **실시간·누적**

라벨에 기준이 드러나야 함 (`주간 풀이` / `총 학습일`).

## ③ 약점 레이더

파트별 축. 총 7개. 강점: 정답률 **70% 이상**, 약점: 정답률 **70% 미만**.

- 축 값 = 누적 파트별 정답률 — **실시간·누적**
- 하단 안내 문구: `전체 기간 누적 풀이 기준 파트별 정답률이에요.`
- **전주 대비 변화(±%p) 표시 제외**

> ±%p를 뺀 이유: 축 값은 누적 정답률인데 델타만 주간(최근 7일 vs 그 전 7일)이라, 한 축에
> 모집단이 다른 두 숫자가 붙음. 학습 초반에는 비교할 전주 데이터가 없어 대부분 빈 값으로 나감.

## ④ 강사 처방전

③에서 정답률 **70% 미만**인 파트 나열. **정답률 낮은 순, 최대 3개.**
파트당 아래 3가지가 한 묶음임.

- **파트 + 정답률** (진행바 포함) — 실시간·누적
- **약점 원인** — YBM 제공 (파트별 고정 문구)
- **연습하기 버튼** — 해당 파트 학습으로 이동
- ~~강사 코멘트~~ **제외**

**색 구간:** 70% 이상 초록 / 55~70% 주황 / 55% 미만 빨강

**처방 대상 파트만 주 1회 고정. 정답률과 진행바는 실시간 변동.**

> 예) 월요일에 Part 7을 약점으로 제시하여 학습자가 학습을 함. 이후 정답률이 70% 이상으로
> 향상하면 새 숙제가 나가게 되므로, **70%를 넘겨도 항목이 사라지지 않고 색만 초록색으로 변경됨**
> (`회복` 배지가 붙음).

## 빈 상태

- **학습 데이터가 없을 때** — ③, ④번 자리에 노출
  `아직 학습 데이터가 없어요. / 문제를 풀면 파트별 정답률과 약점 분석이 여기에 쌓여요.`
- **약점 파트가 0개일 때** (모든 파트 70% 이상) — ④ 안에 노출
  `이번 주 약점 파트가 없어요 👏 / 모든 파트 정답률이 70% 이상이에요.`

## YBM이 전달할 데이터

| 항목 | 형태 | 현재 상태 |
|---|---|---|
| 파트별 약점 원인 문구 | 파트당 1문장 | **P1·P2 비어 있음** (폴백 문구로 나감) |

강사 코멘트가 빠지면서 강사 × 파트 매트릭스는 더 이상 필요하지 않음.

## 확인이 필요한 사항

**1. ①과 ②의 정답률 계산식이 다름**
- ① 전체 정답률 = `총 정답 수 / 총 풀이 수` (**문항 가중**)
- ② LC/RC 정답률 = `해당 파트들의 정답률을 단순 평균` (**파트 가중**)

→ 5문항 푼 파트와 200문항 푼 파트가 LC/RC에서는 같은 무게임. **LC·RC의 평균이 ①과
일치하지 않을 수 있음.** 의도한 것인지 확인 필요.

**2. `누적 n문제`의 분모와 정답률 분모가 다를 수 있음**
`누적 n문제`는 답안 로그 전체 건수인데, 정답률 분모는 파트가 매칭된 로그만 셈.
문항 정보를 못 찾은 로그가 있으면 두 숫자가 어긋남.

**3. 온보딩 시 데모 baseline이 심김**
현재 목업은 프로필 저장 시점에 파트별 정답 로그를 계정에 심어(`ensureBaselineAnswerLog`)
레이더가 설계된 약점 모양(P1 90% … P7 48%)을 그리게 함.
**MVP1에서 이 시딩을 유지할지 결정 필요.** 빼면 신규 사용자는 한동안 빈 리포트를 봄.

**4. 70% 기준선이 목표 점수와 무관하게 고정임**
목표 750점 학습자와 900점 학습자의 '약점' 기준이 동일함. 앱에 `targetScore`가 이미 있으므로
목표에 따라 기준선을 움직이는 방안 검토 가능(예: 700점대 70% / 900점대 85%).
고득점 학습자일수록 ④가 빈 상태가 되어 **연습하기 동선이 끊기는** 문제도 함께 해소됨.

**5. 처방 대상 파트 목록의 저장 위치**
현재 목업은 브라우저(localStorage)에 저장해 기기를 바꾸면 그 주 처방이 다시 뽑힘.
MVP1에서는 **계정 단위 서버 저장**으로 가야 주중 고정이 보장됨.
