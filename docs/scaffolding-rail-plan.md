## 0. 왜 하는 일인가

콘텐츠팀이 **개발자 없이 스캐폴딩을 바꿔가며 테스트**할 수 있게 만드는 것. 궁극적으로는
강의가 수만 개로 늘어도 **최소한의 장치로 돌아가는 구조**를 만드는 것.

출발점의 문제: 수업 화면이 DB에서 가져오는 건 **문항 내용뿐**이었고, 스캐폴딩 순서(턴)는
`src/data/typeLearning/fromDb.ts`가 코드로 찍어내고 있었다. 시트를 고쳐도 스캐폴딩은 안 움직였다.

목표 구조:

```
부품 사전 (rail_steps)          ← 무엇을 시키는 턴인가. 파트별 최소 단위
      ↓ 조합
조합표 (rail_compositions)      ← 유형(강의)이 부품을 어떤 순서로
      ↓ + 문항 DB(questions)
문구는 LLM이 매번 생성          ← 강의가 늘어도 부품은 그대로
```

## 1. 지금까지 한 것

### 1-1. DB 레일 구동 ✅

`lecture_steps`에 사람이 쓴 한국어 문장을 화면 동작으로 옮긴다.

| 파일 | 역할 |
|---|---|
| `src/data/typeLearning/fromSteps.ts` | **번역기.** 문장 → `Turn[]` + 해석 결과·경고 |
| `src/data/db/lectureStepStore.ts` | 레일 로더. `rail_compositions` → `lecture_steps` → 없으면 빈 배열 |
| `src/components/type-lesson/RailInspector.tsx` | 검토 패널 (우하단 🧩) |
| `src/app/type-lesson/[typeId]/page.tsx` | 배선 |

`fromDb.ts`는 **건드리지 않았다.** 콘텐츠 조립(사진·지문·보기·근거)은 그대로 쓰고 `turns`만 교체.
레일이 없거나 못 쓰면 기존 코드 레일로 폴백한다.

**번역 커버리지** (이도윤 레일 364턴 실측):

| 칸 | 해석 성공 | 비고 |
|---|---|---|
| `interaction` | **364 / 364** | 19가지 표현 전부 |
| `script_mode` | 356 / 364 | 미지원 8 = 질문·발화 스크립트 (Part2·3용) |
| `audio_mode` | 300 / 364 | **실패 64건 전부 Part3·4** |

`audio_mode` 실패는 사전을 늘려서 해결되지 않는다:

> `"음원을 처음부터 재생한다. 근거가 명확하면 멈추고, 불명확하면 Q1을 보류한다."`

화면이 '근거가 명확한지'를 판단할 수 없다. **AI 튜터가 읽을 문장이지 플레이어가 실행할 명령이
아니다.** 경고만 남기고 무시한다. 지금 DB로 도는 4개 강의(P1·P5·P6·P7)에는 없다.

**쓸 수 있는 표현 (콘텐츠팀에 전달해야 함)**

- `interaction` — `AI 진행` / `선택 응답` / `필수 응답` / `주관식 응답` / `필수 수행`(`필기 인식`·`쉐도잉`·`매칭`)
- `script_mode` — `표시 없음` / `A 스크립트만 표시` / `전체 스크립트 공개`
- `audio_mode` — `재생 없음` / `선택지 A 음원만 재생한다` / `선택지 A~C를 이어서 재생한다` / `전체 음원을 처음부터 끝까지 재생한다`

`supabase/migrations/0011_rail_components.sql` · `scripts/import-rail-components.js`

### 1-3. 학생 문구 LLM 생성 ✅

`src/app/api/rail-prompts/route.ts` · `src/data/typeLearning/railPrompts.ts`

문구를 강의마다 손으로 써두면 강의가 늘 때 사람이 따라 써야 한다 → 확장 불가.
그래서 **부품 + 이번 문항 사실**로 매번 만든다.

```
우선순위:  override(예외) > LLM 생성 > 부품 기본값 / 이식 seed
```

이식된 손글씨 문구는 버리지 않고 `*_seed`로 내려서 **LLM 말투 예시 + 오프라인 폴백**으로 쓴다.
그 결과 `student_prompt_override`는 현재 **0개**.

> **`override` 개수 = 확장성 지표.** 여기에 값이 생기면 "이 강의만 예외"라는 뜻이다. 0을 유지해야 한다.

실증: DB에 그 문장이 없는데도 `"주어와 빈칸 뒤 by구문을 찾아 표시해 보세요."`가 생성됐다.
(원본 손글씨는 `"주어와 by구문, 목적어 유무를 표시해보세요."`)

### 1-4. 화면 문구 vs 강사 발화 — 구분 정리

혼동이 잦은 지점이라 못 박아둔다.

| | 만드는 주체 | 경로 |
|---|---|---|
| **강사 발화** (말풍선 + 목소리) | **ElevenLabs 에이전트** | `turn.tutor` → `directiveOf()` → 에이전트가 자기 말투로 |
| **화면 UI 문구** (배너·버튼 라벨) | React가 그리는 텍스트 | `Interaction.prompt` ← 이번 작업으로 LLM 생성 |

에이전트가 UI 문구를 만들 수 없는 이유: ①턴이 뜨는 순간 배너·버튼이 이미 있어야 함(에이전트는
그 뒤에 말함) ②에이전트는 음성 스트림이라 화면 문자열을 리턴하지 않음 ③에이전트 연결이 없어도
화면은 떠야 함.

## 3. 다음 할 일

### P0 — `mark`(단어 짚기) 턴 정답 체크 복구

기존 코드 레일은 Part5에서 **빈칸 앞뒤 단어를 계산해서** `targetWords`에 넣어줬다
(`fromDb.ts`의 `blankNeighbors()`). DB 레일엔 그 정보가 없어서 지금은 **아무 단어나 짚어도 넘어간다.**

수업 품질에 바로 걸리는 퇴보라 이게 제일 먼저다. 방향 후보:

1. `fromSteps.ts`에서 파트별로 계산해 채우기 (P5=빈칸 앞뒤, P7=근거 문장) — 빠르지만 코드에 로직이 돌아옴
2. `/api/rail-prompts`처럼 LLM이 "짚어야 할 단어"를 문항에서 뽑기 — 구조상 일관됨
3. 부품에 `target_rule` 칸을 두고 `빈칸 앞뒤` / `근거 문장` 같은 값으로 지시

→ **2번 권장.** 문구 생성과 같은 자리에 얹으면 API 호출이 늘지 않는다.

### P0-b — RC-P6-01 첫 턴 `interaction` 오기입 (콘텐츠팀 수정 필요)

브라우저 확인 중 경고 1건이 잡혔다. **시트 값이 서로 모순인 자리다.**

```
step_code      : S4 지문 읽기 시작
interaction    : 선택 응답 또는 AI 진행           ← 이게 문제
student_prompt : "이메일이죠? 발신자와 수신자에 동그라미 치세요"
fixed_rule     : "…이 단계에서는 선택지를 보더라도 정답을 고르지 않고,
                  '이 글이 무슨 상황인지'만 확인한다"
```

규칙은 "정답을 고르지 않는다"인데 `interaction`은 "선택 응답"이다. `student_prompt`도
"동그라미 치세요"니 **필기 인식**이 맞다. 지금은 화면이 `interaction`만 보고
**첫 턴부터 Q1 정답을 고르라고 시킨다** (지문도 안 읽었는데).

다른 강의 첫 턴은 전부 `필수 수행 / 필기 인식` 계열이라, 이 강의만 튄다.

→ **시트에서 `필수 수행 / 필기 인식`으로 고치면 해결.** DB 직접 수정 금지(새벽 크론이 덮음).
경고를 띄우게 해둔 덕에 잡혔다 — 안 그랬으면 조용히 잘못 돌았을 자리.

### P4 — S단계를 실제 단위로 승격할지 결정

`step_types`(S1~S7) 테이블은 있지만 `lecture_steps`가 **참조하지 않는다.** `step_code`는 자유 텍스트고:

- **115턴**이 S코드 2개 이상 섞임 (`Q1-S5 + 쉐도잉 + S6`)
- **34턴**은 S코드가 아예 없음 (`전체 음원 재생 + 학생 풀이`)

그래서 지금 **최소 단위는 턴이고, `S6`로 조회·수정이 불가하다.** 이걸 바꾸려면 한 턴에 S가 여러 개
섞인 115턴을 어떻게 쪼갤지 **콘텐츠팀이 정해야 한다** (쪼개면 음원·스크립트 지시는 어느 줄에 붙나?).

턴 단위로도 순서 변경·삭제·문구 변경 실험은 다 되므로 급하지 않다.

### P5 — 별도 실험 툴 레포 (원래 요청, 아직 안 함)

처음 요청은 **이 화면만 떼어 별도 레포·별도 링크의 스캐폴딩 검토 툴**을 만드는 것이었다.
"먼저 이 프로젝트가 DB대로 돌게"로 방향이 바뀌어 아직 안 했다.

지금 상태에서 다시 보면 **떼는 필요성이 줄었다** — 콘텐츠팀은 DB(시트)만 고치면 되고, 레일 검토
패널이 해석 결과를 보여준다. 다만 여전히 필요할 수 있는 것:

- 로그인·온보딩 없이 바로 들어가는 링크
- 강의·강사를 드롭다운으로 골라 아무 조합이나 재생 (지금은 `DB_ANCHOR`에 박힌 4개만)
- 여러 레일 버전 나란히 비교

→ 별도 레포보다 **이 레포에 `/rail-lab` 라우트 하나** 만드는 게 싸고 안 갈라진다. 판단 필요.

### 시트 ↔ DB 7칸 어긋남 (미해결)

`lecture_steps`가 시트 최신본보다 뒤처져 있다. 이도윤 `LC-P1-01`·`LC-P1-02`의 `student_prompt` 7칸.
7/21에 받은 덤프 = 현재 DB이고, 그 뒤 시트가 수정됐다 (일반 템플릿 문구 → 그 사진 전용 구체 발화).
**작업 중인 시트로 보여 일부러 당기지 않았다.** 그쪽 작업이 끝나면:

```bash
node scripts/dump-sheet.js "[이도윤 ver] 스케폴딩 (유형학습_G)_초안(0713)"
node scripts/import-instructor-rails.js
```

⚠️ **`import-instructor-rails.js`의 `CONFIG.dump` 파일명이 옛 탭 이름(`_초안 수정 완료(0713)`)이다.**
시트 탭이 `_초안(0713)`으로 바뀌었으니 파일명도 같이 고쳐야 한다. 안 고치면 옛 덤프를 다시 넣는다.

윤다은 레일은 시트와 **완전 일치**(40강 302스텝, 차이 0).

### 구글 시트 토큰

`scripts/token.json`은 만료됐다(`invalid_grant`). **`scripts/token_sheets_rw.json`은 살아있고**
Python 형식이라 Node에서 쓸 때는 `OAuth2` + `setCredentials({refresh_token})`으로 붙여야 한다.
`scripts/google-auth.js`는 `token.json`만 보므로 재인증하거나 우회해야 한다.

### Gemini

- `.env.local`에 `GEMINI_API_KEY` 있음 (커밋 안 됨 — **배포 시 Vercel 환경변수에 별도 등록 필요**)

### dev 서버 함정

**`next dev`가 도는 중에 `npm run build`를 돌리면 `.next`가 덮여 dev 서버가 깨진다**
(`MODULE_NOT_FOUND` / CSS 없는 깨진 화면). 코드 문제가 아니다. 고치는 법:

```bash
# 포트 잡은 프로세스 종료 후
rm -rf .next && NODE_OPTIONS="--max-old-space-size=4096" npm run dev
```
