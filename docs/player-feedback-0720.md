## W1. RC 다중지문 잠금 해제 (슬라이드 13-①) — 가장 쉬움, 명시적 변경 요청

> "목업에는 지문이 잠겨있는 경우가 있으나 **자유롭게 학생이 오갈 수 있게 잠금 없이** 가는 방안으로 진행"

- 현행: `RevealState.passageIds`로 지문을 점진 공개, 잠긴 지문은 자물쇠 탭 + "순서가 되면 열려요" 플레이스홀더.
- 변경: **P6·P7 지문은 처음부터 전부 열람 가능.**
  - 최소 수정: `TypeLessonPlayer.tsx`에서 ContentState 조립 시 `revealedPassages`를 항상 `'all'`로 넘긴다
    (파생 계산을 지우지 말고 마지막에 override — 다른 파트/스크립트 reveal 로직은 건드리지 말 것).
  - `ContentView.tsx`의 잠금 UI(`PassageView` 상단 잠금 분기, `PassageTabs`의 `locked` 자물쇠 아이콘)는
    도달 불가 코드가 되면 제거해도 되고 남겨도 됨 — 남기면 나중에 정책 뒤집기 쉬움. 제거한다면 둘 다 제거.
  - 데이터(`lessonsRC.ts`)의 `reveal.passageIds`는 **지우지 말 것** — "새 지문이 공개되면 그 탭으로 자동 이동"
    로직(`PassageTabs`의 revealedIds 증가 감지)이 이를 "지금 다루는 지문" 신호로 재활용할 수 있다.
    revealedPassages를 'all'로 밀면 이 자동 탭 전환이 죽으므로, **턴의 `reveal.passageIds`를 별도 prop
    (예: `activePassageId`)으로 넘겨 탭 자동 전환은 유지**할 것.
- 확인: `/type-lesson/t13`(또는 P7 삼중지문 유형) 진입 직후 지문 탭 3개 모두 클릭·열람 가능,
  턴이 진행되며 다루는 지문으로 탭이 따라오는지.

## W2. 문항 탭 — 한 화면에 한 문항 (슬라이드 7·9-3.1, 8·10-4.1, 13-③)

> 문제 영역 상단에 Q1/Q2/Q3 탭, 탭 클릭으로 이전/이후 문항 자유 이동. LC P3/4 + RC P6/7 대상.

- 현행: `ContentView.tsx`가 `questionsBlock`으로 전 문항을 세로 스택. `focusQ`인 카드만 강조+스크롤.
- 변경: 문항이 2개 이상인 P3/4/6/7에서 스택 → **탭 + 단일 카드**.
  - 새 컴포넌트 `QuestionTabs` (PassageTabs와 같은 패턴): 상단 탭 줄 + 활성 문항 카드 1개.
  - 탭 상태는 로컬 state. 단, **`focusQ`가 바뀌면 그 문항 탭으로 자동 전환** (사용자가 다른 탭을 보다가도
    턴이 진행되면 따라오게 — PassageTabs의 자동 전환과 같은 UX).
  - 탭 뱃지: 채점된 문항(`graded`)은 정/오답 표시(초록/빨강 점), 현재 `focusQ`는 파랑 강조.
  - `solveAll`(실전 풀이) 모드에서는 전 문항을 다 봐야 하므로 탭 이동이 자유로워야 하고,
    답 선택 여부를 탭에 점으로 표시하면 좋다.
  - P1·P2·P5는 문항 1세트 구조라 그대로 둔다.
- 확인: t07(P3)·t13(P7)에서 Q 탭 전환, 턴 진행 시 자동 탭 이동, 실전 단계에서 전 문항 답 선택 가능.

## W3. LC 전체 음원 재생 바 (슬라이드 5~10 공통 항목)

> 전체 음원 재생 버튼(바) 추가. **1차 청취(문제 푸는 단계) 중에는 학생 제어 불가**,
> 1차 청취 후에는 다시 재생·멈춤·바 이동 가능.

- 현행: 음원은 턴의 `audio` 큐(`AudioCue`)로만 재생 — 학생이 조작할 수 있는 플레이어 UI가 없다.
- 변경: LC(P1~P4) 화면 상단(스텝 레일 아래, 본문 위)에 오디오 바 컴포넌트 추가.
  - 상태 2단계:
    1. **잠김(1차 청취 전/중)**: 진행 표시만 보이고 버튼·시크 비활성(회색 자물쇠 톤).
    2. **해제(1차 청취 완료 후)**: 재생/일시정지 + 문장 단위 진행 바.
  - "1차 청취 완료" 판정: `audio.kind === 'full'` 큐가 있는 턴이 끝났을 때 플래그
    `fullListenDone=true`. P1·P2처럼 full 큐가 없는 유형(보기만 음성)은 **정답 공개 시점**
    (`graded`에 focusQ 추가되는 순간)에 해제.
  - ⚠️ **브라우저 TTS 제약**: SpeechSynthesis는 임의 시크가 안 된다. 시크 바는 **문장 인덱스 기반**으로
    근사한다 — 바를 n번째 문장 위치로 클릭하면 그 문장부터 `speakEnglishSeq(items.slice(n))` 재생.
    진행률 = 재생 중 문장 idx / 전체 문장 수. 일시정지는 `stopVoice()` + 현재 idx 기억 → 재생 시 이어서.
    mp3 이관 때 진짜 시크로 교체한다는 주석을 남길 것.
  - 재생 중 문장은 기존 `playingId` 하이라이트 그대로 활용.
- 확인: t07 진입 → 전체 듣기 턴 전에는 바 조작 불가 → 듣기 턴 종료 후 재생/일시정지/문장 점프 동작.

## W4. P3/4 스크립트 문장 클릭 → 개별 문장 재생 (슬라이드 7~10의 2.3)

- 현행: `ScriptAccordion`의 문장 행은 표시 전용(재생 하이라이트만).
- 변경: 공개된 문장 행 클릭(또는 행 우측 스피커 아이콘 클릭) 시 그 문장만 `speakEnglishSeq([그 문장])` 재생.
  재생 중 다른 문장을 클릭하면 기존 재생 취소 후 새 문장(voice.ts의 `_seq` 토큰이 이미 처리).
  - 단어 탭 형광펜(TapText)과 클릭이 겹치므로: **단어 스팬 클릭은 형광펜, 행의 여백/스피커 아이콘 클릭은 재생**으로
    분리한다(행 onClick에서 `e.target` 검사보다는, 행 끝에 재생 버튼을 명시적으로 두는 쪽이 단순).
- W3의 오디오 바와 같은 재생 파이프라인을 쓰므로 W3 다음에 하는 게 편하다.
- 확인: t07 정답 공개 후 스크립트 열고 문장별 재생 버튼 클릭.

## W5. P1/P2 선택지 컨트롤 — 재생·쉐도잉·스크립트 버튼 (슬라이드 5·6의 3.1~3.3, 6의 2.1~2.2)

> 선택지마다: ① 클릭 시 음원 재생 ② 쉐도잉 버튼 ③ 스크립트 토글 버튼.
> ②③은 **강사가 정답 공개 또는 선택지 코칭을 한 후 활성화**. P2는 질문 카드에도 재생+쉐도잉 버튼.

- 현행: 보기 음원은 턴 큐로만 재생. 쉐도잉은 `shadow` 턴이 올 때만 하단 독에서 수행.
  선택지 텍스트는 `reveal.optionText`로 턴이 공개.
- 변경 (`ContentView.tsx`의 `QuestionCard`, P1/P2 한정 — `lesson.content.optionAudio`가 true인 유형):
  - **재생**: 보기 행 좌측 스피커 아이콘 클릭 시 그 보기 음원 재생(`AudioCue {kind:'option'}`과 같은 소스).
    답 선택 버튼과 겹치지 않게 아이콘은 별도 클릭 타깃으로.
  - **쉐도잉 버튼**(행 우측 `쉐도잉 ▶`): 클릭 시 그 보기 음원 재생 → 끝나면 en STT 마이크 오픈
    (기존 `shadow` 인터랙션의 마이크 컴포넌트 `TypeLessonPlayer.tsx`의 STT 부분 재사용).
    발음 평가 없음 — 인식 텍스트만 보여주면 된다.
  - **스크립트 토글 버튼**(행 우측 아이콘): 클릭 시 그 보기 텍스트 표시/숨김. 기존 `revealed`(턴 공개)와
    별개의 로컬 토글 state로 두고, `표시 = 턴공개 OR 로컬토글` 로 합성한다.
  - **활성화 조건**: 쉐도잉·스크립트 버튼은 `graded.has(qIdx)`(정답 공개) **또는 그 보기가
    `reveal.optionText`로 공개된 뒤(선택지 코칭 후)** 활성. 그 전에는 회색 disabled.
  - **P2 질문 카드**: 질문 재생 버튼(기존 스피커 원형을 클릭 가능하게) + 우측 `쉐도잉 ▶` 버튼.
    활성화 조건 동일(질문은 1차 청취 후).
- 확인: t01(P1)·t02(P2)에서 코칭 전 버튼 disabled → 정답 공개 후 재생/쉐도잉/스크립트 토글.

## W6. P3/4 문장별 쉐도잉 버튼 (슬라이드 11)

> 스크립트의 **모든 문장에 개별 쉐도잉 버튼**. 스캐폴딩 쉐도잉 단계(S5)부터 활성화.
> 쉐도잉 1차 재생은 강사 주도(학생 제어 X), 발음 평가 없음. Part3 대화·Part4 담화 공통.

- 현행: `shadow` 턴이 지정한 `chunks`만 하단 독에서 쉐도잉.
- 변경: `ScriptAccordion` 문장 행에 `쉐도잉 ▶` 버튼 추가 (W4 재생 버튼 옆).
  - 동작: 그 문장 재생 → 끝나면 en STT 마이크 오픈 → 인식 텍스트 표시. 평가/채점 없음.
  - 활성화: 레일이 쉐도잉 단계에 도달한 뒤부터 (`turns[0..idx]` 중 `interaction.kind === 'shadow'`인
    턴이 등장했는지로 판정 — 기존 공개범위 파생 패턴과 동일하게 인덱스에서 파생할 것).
  - 기존 `shadow` 턴(하단 독의 따라말하기)은 그대로 둔다 — 강사 주도 1차 쉐도잉이 그 턴이고,
    이 버튼은 그 이후의 자율 반복용.
- 확인: t07에서 쉐도잉 턴 전에는 버튼 미노출(또는 disabled) → 쉐도잉 턴 이후 문장별 쉐도잉 가능.

## 구현 순서 권장

`W1 → W2 → W3 → W4 → W5 → W6` (W1·W2는 독립·저위험, W3이 오디오 파이프라인 기반, W4~W6이 그 위에 얹힘).
각 W는 별도 커밋. 커밋 전 `npm run build` 필수.

## 공통 주의사항

- **엔진은 상호작용 kind로만 분기**한다 — 특정 유형(t07 등) 하드코딩 금지. 파트 번호(`lesson.part`) 분기는 허용.
- 새 버튼/바는 기존 디자인 토큰 그대로: 파랑 `#2563EB`, 테두리 `#E5E7EB`, 라운드 `rounded-xl/2xl`,
  글씨 `text-[11~13px] font-bold`. 기존 컴포넌트(예: `SpeakerIcon`) 재사용.
- 음성은 전부 `src/lib/voice.ts` 경유(`speakEnglishSeq`/`stopVoice`). 화면 이탈 시 `stopVoice()` 유지.
- 문장별 mp3 이관이 다음주 예정 — voice.ts 인터페이스(id+text 목록)를 깨지 말 것.
- 이 문서의 슬라이드 번호는 덤프 JSON의 `slides[].n`과 일치한다. 원문 확인이 필요하면 덤프를 읽을 것.

## 유형(t01~t15) ↔ 파트 빠른 참조

라우트는 `/type-lesson/<id>`. 어느 id가 어느 파트인지는 `src/data/typeLearning/index.ts`와
`lessonsLC.ts`/`lessonsRC.ts`의 `part` 필드에서 확인하고 작업할 것 (P1·P2 = LC 앞 유형,
P3·P4 = LC 묶음, P5~P7 = RC).
