01무엇을 사는가

실시간 AI 강사는 네 개 층으로 구성된다. 우리는 이 중 얼굴 층만 없다.

층역할우리 현황

03연동 방식 3안

Tavus는 4개 층을 묶어 판매한다. 어디까지 대체할지에 따라 3안이 나온다.

안Tavus 담당우리 담당평가
A · 전체 인식·판단·발화·얼굴 — 구축 최속. 단 레일·단계 게이트가 전부 무효가 되어 화면·발화 불일치 문제가 재발
B · 판단만 자체 권장 인식·발화·얼굴 판단(LLM) 수업 설계를 유지한 채 얼굴만 확보. 연동 규격이 업계 표준이라 접합 용이
C · 얼굴만 얼굴 인식·판단·발화 완전 통제 + 기존 음원 재활용. 단 턴 교대·끼어들기 제어를 전부 자체 구현해야 함
B안 권장 근거

A안은 docs/tutor-control-plan.md 기준으로 구축한 발화 통제 구조를 폐기하게 된다. 해당 문제는 실시간 적용 구간이 길어질수록 커진다.

개발 범위 — 자체 튜터 서버를 OpenAI /chat/completions + SSE 규격으로 노출하는 어댑터 1종. 설정은 base_url·api_key·model 3개.

3안의 비용은 동일하다

Tavus 요금은 세션 분 단위 단일 과금이며 층별로 나눠 사지 않는다. B·C안으로 층을 덜어내도 분당 단가는 그대로이고, 자체 LLM·TTS 비용이 그 위에 추가된다. 즉 3안의 선택 기준은 비용이 아니라 수업 통제권이다.

06실측 필요 항목

공개 자료로 판단 불가한 항목이다. 1·2번 중 하나라도 실패하면 도입 불가다.

#항목쟁점실패 시
1한국어 립싱크 한국어 음소 기준 학습 여부 비공개. 영어권 서비스의 통상 취약점 도입 불가

3국내 실지연 공식 600ms는 영어 추정치. 리전 비공개, 한국어는 저속 엔진 강제 — 4장 설계 변경 1.5초 초과 시 수업 리듬 붕괴
4자체 음원 립싱크 기존 강사 음원 503개 재활용 가능 여부 비용 증가 보이스 재제작
5앱(Expo/RN) 구동 공식 SDK 없음. 기반 인프라(Daily)의 RN 라이브러리로 직접 구현. 자사 서비스가 앱 기반이므로 웹 검증만으로는 판단 불가 설계 변경 웹뷰 방식 대체 검토
