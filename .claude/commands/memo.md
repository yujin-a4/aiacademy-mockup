콘텐츠 파트(강유진·주민정)가 화면을 직접 만져 보고 적은 **버그·개선 접수 창구**를 처리한다.
정본은 시트 "AI어학원 콘텐츠" 탭 `FGI 구현 중 메모`. 서비스 계정으로 읽고 쓴다(사람 로그인 불필요).

## 1. 열린 건을 읽는다

```bash
PYTHONIOENCODING=utf-8 python scripts/memo.py list        # 열린 건만 (회신이 있으면 💬 로 뜬다)
PYTHONIOENCODING=utf-8 python scripts/memo.py show <행>    # 한 행 전체
```

🔴 **I 열(회신)을 반드시 읽는다.** 머리말이 비어 있어서 08-24 실측 때 빠뜨렸고, 그 바람에
41행에 이다원 님이 *"RC 유형학습 4에 강사 정/오답 답변이 누락되어 노란색 셀로 추가해뒀으니 그
부분만 반영해달라"* 고 적어둔 걸 못 본 채 `반영 후 확인 중` 으로 두고 있었다(08-26 발견).

I 열은 양쪽이 주고받는 **대화 칸**이다 — 결정·재요청·신규 제보가 다 여기로 들어온다.
`J` 가 `반영 완료` 인 행에도 새 요청이 붙어 있을 수 있으니, **회신이 있으면 J 를 믿지 말고 읽는다.**

`$ARGUMENTS` 에 행번호가 있으면 **그 행들만** 다룬다. 없으면 열린 건 전부를 아래처럼 가른다.

🔴 **셀에 띄워 넣은 사진은 시트 API 로 안 읽힌다.** 값이 아니라 오버레이라서 `memo.py` 도
`sheet_sa.py` 도 빈칸으로 본다. 콘텐츠 파트는 **G·H 칸에 스크린샷을 자주 붙인다** — 그게 정본이다.

- 글자만 읽고 "찾았다" 고 단정하지 않는다. 08-26 에 37행 사진을 못 본 채 grep 결과만 보고
  **엉뚱한 파트(P6)를 고쳤다.** 되돌리는 데 한나절 걸렸다.
- 글로 적힌 증상이 **어느 화면인지 딱 떨어지지 않으면 사진이 있는지부터 의심하고 사용자에게 청한다.**
  "H열 사진을 이 창에 붙여 주세요" 한 마디면 된다.

## 2. 세 갈래로 가른다 — 이게 이 명령의 핵심이다

| 갈래 | 뜻 | 할 일 |
|---|---|---|
| **A. 그냥 고친다** | 제품 결정이 필요 없다. 명백한 오류·오타·빠진 처리 | 고치고 시트에 되적는다 |
| **B. 확인해야 안다** | 재현부터 해야 한다 | 브라우저로 확인(`docs/screens`·`/dev/screens`)한 뒤 A 나 C 로 보낸다 |
| **C. 결정이 필요하다** | "필기도구를 자동으로 켤까?" 같은 **선택** | **고르지 말고 `docs/DECISIONS.md` 에 블록으로 쌓는다.** 그리고 보고에 한 줄로 올린다 |

C 를 혼자 정하지 않는 게 제일 중요하다. 과거에 자동 처리하려다 걸린 지점이 늘 여기였다.
그리고 **말로만 묻지 않는다** — 08-25 에 같은 걸 네 번 묻고도 답을 못 받았다. 물었으면
`docs/DECISIONS.md` 에 남는다. 시작할 때 그 파일부터 읽고, `**답:**` 이 채워진 블록을 먼저 처리한다.

## 3. 고칠 때 지키는 것

- **데이터를 고치지 엔진을 고치지 않는다** — 대부분은 `src/data/*Scenario.ts`·시트 쪽이다(CLAUDE.md §4).
- **생성물은 손으로 못 고친다** — `fgiScenario.ts` 는 훅이 막는다. 시트를 고치고 생성기를 다시 돌린다
  (`node scripts/build-fgi-scenario.js --go` → `python scripts/audit-fgi.py`).
- **검사는 `npx tsc --noEmit`** — `npm run build` 는 dev 서버의 `.next` 를 깨뜨린다(훅도 막는다).
- 브랜치 → develop PR → main PR **한 쌍**으로 나간다. 콘텐츠팀이 QA 하는 화면은 **main** 이다.
- 커밋 하나에 한 건. 메시지에 몇 행짜리인지 적는다 (`fix(lesson): … (메모 23행)`).

## 3.3 화면을 **말로 설명하기 전에 그리는 코드를 읽는다**

코드의 데이터 쪽만 읽고 화면을 짐작해 그리면 그럴듯한 거짓말이 나온다. 08-26 에 Part 5 실전이
"지문 3문장이 다 보이고 (1)(2)(3) 번호 상자가 있다" 고 **그림까지 그려 설명했는데 전부 지어낸
것이었다.** 실제로는 문장 카드 1 + 문항 카드 1 이 한 화면이고 빈칸은 번호 없는 `______` 하나다.

- 화면 모양을 근거로 뭔가를 주장하려면 **렌더 코드(`ContentView.tsx` 등)를 열어서 본다.**
- 못 읽었으면 그리지 말고 **"확인 안 함"** 이라고 적는다. 짐작을 그림으로 그리면 사용자가 그걸
  사실로 읽는다.
- 데이터에 있는 값 ≠ 화면에 나오는 글자다. 마커 하나(`______` vs `___(n)___`)로 갈린다.

## 3.4 먼저 **기계에게 채점시킨다** — `npm run smoke`

타입 검사는 "안 깨졌다" 만 말한다. 스모크 검사는 **"어제와 달라졌다"** 를 말한다.
`/dev/screens` 갤러리의 화면을 하나씩 열어 눈에 보이는 글자·버튼 상태를 찍고
`tests/smoke/baselines/` 의 기준과 글자 단위로 비교한다. 캡처가 아니라 글자다 — 값싸고 정확하다.

```bash
npm run smoke                 # 전부. dev 서버가 떠 있어야 한다
npm run smoke -- --serve      # 없으면 직접 띄우고 끝나면 내가 내린다
npm run smoke -- end-fb-high  # 몇 개만
```

**읽는 법이 곧 이 검사의 값어치다.**

| 결과 | 뜻 | 할 일 |
|---|---|---|
| 통과 | 내가 안 건드린 화면이 그대로다 | 넘어간다 |
| **탈락 — 내가 고친 화면** | 의도한 변화다 | diff 를 **읽고 맞는지 확인한 뒤** `npm run smoke -- --update <id>` |
| **탈락 — 안 건드린 화면** | 🔴 **곁다리 사고다.** 이게 이 검사를 만든 이유다 | 고치고 다시 돌린다 |

**정지 조건: 세 번 돌려도 탈락이 안 없어지면 멈추고 보고한다.** 무한히 되풀이하지 않는다.
`--update` 는 **일부러 줬을 때만** 기준을 덮는다 — 탈락을 없애려고 습관적으로 붙이면
이 검사는 그 순간 아무 말도 안 하는 검사가 된다.

못 보는 것: **강의 화면(`lecture:*`)** 은 DB 문항이 늘면 같이 바뀌어 기준을 못 잡는다(이름으로
콕 집어 부를 때만). 목소리·억양·손의 감각도 못 본다 — 아래 ③등급 그대로다.

## 3.5 그래도 **눈으로 본다** — 스모크가 통과했어도

스모크는 글자만 본다. 색·자리·타이밍은 못 본다. 콘텐츠 파트가 보는 건 화면이라,
**고친 화면 한둘은 여전히 눈으로 봐야** 고쳤다고 할 수 있다.

**dev 서버 — 이 명령 안에서는 내가 띄워도 된다** (2026-08-24 사용자 허락). 평소 규칙은
[[dev-server-owned-by-user]] 대로 "내가 안 띄운다" 이고, 그 예외는 **`/memo` 안에서만** 이다.

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000     # 먼저 본다
```

- **이미 떠 있으면 손대지 않는다.** 사용자 것이다 — 죽이지도, 다시 띄우지도 않는다.
- 안 떠 있을 때만 `npm run dev` 를 **백그라운드로** 띄운다. 포트는 3000 하나만 쓴다
  (여러 개가 같은 `.next` 를 물면 서로 깨뜨린다).
- **내가 띄운 것은 끝나면 내가 내린다.** 내린 사실을 보고에 적는다. 사용자 것은 그대로 둔다.
- **`npm run build` 는 절대 같이 돌리지 않는다** — `.next` 를 덮어 dev 를 죽인다(훅도 막는다).
  검사는 `npx tsc --noEmit` 이고, dev 가 떠 있으면 그것도 메모리로 터질 수 있다
  ([[dev-server-memory-limit]]) → 그때는 **먼저 검사하고 나서 서버를 띄운다.**
- 웹팩 gzip 할당 실패로 죽으면 코드를 의심하지 말고 `rm -rf .next` 뒤 힙 4GB 로 다시.

크롬 확장이 안 붙어 있으면 `claude-in-chrome` 스킬을 부른 뒤 `tabs_context_mcp` 로 확인한다.
확장이 없으면 화면 확인은 못 한다 — 사용자에게 알리고 `반영 후 확인 중` 으로 남긴다.

**세 등급으로 갈라 놓는다. 등급을 올려 말하지 않는다.**

| 등급 | 무엇 | 어떻게 |
|---|---|---|
| ① 바로 본다 | 화면 글자·표시·버튼 상태 | **`npm run smoke` 가 이미 봤다**(§3.4). 색·자리처럼 글자가 아닌 건 화면을 열고 읽는다 |
| ② 수를 쓴다 | 말(STT)·LLM 응답·실패 갈래 | `javascript_tool` 로 가로챈다 — 인식기를 감싸 가짜 전사를 밀어넣거나, `fetch` 를 덮어 빈 응답을 만든다 |
| ③ 못 한다 | 목소리 품질·억양·손의 감각 | **못 했다고 적는다.** 콘텐츠 파트가 들어야 닫히는 건이다 |

수업 화면의 특정 턴으로 가려면 상단 스테퍼를 누른다(`DEV_PHASE_JUMP`). 음성 가로채기 요령은
메모리 [[fgi-scripted-lesson]] 의 "브라우저로 직접 확인할 수 있다" 에 코드째 적혀 있다.

**시트에 적을 때 등급이 곧 값이 된다.**
- 스모크가 통과했거나 내 눈으로 화면에서 확인함 → `반영 완료`
- 고쳐서 머지했지만 화면은 못 봄 → `반영 후 확인 중` (여기가 기본값이다)
- 일부만 → `일부 반영`, 못 고침 → `실패`

**확인 못 한 것을 확인한 것처럼 적지 않는다.** 그 한 줄 때문에 콘텐츠 파트가 QA 를 건너뛴다.

## 4. 시트에 되적는다

```bash
PYTHONIOENCODING=utf-8 python scripts/memo.py done <행> "<수정 여부>" "<무엇을 어떻게 했는지 (PR #번호)>"
```

- **J(수정 여부)는 드롭다운이다.** 여섯 값뿐: `수정 중`·`반영 후 확인 중`·`반영 완료`·
  `반영 완료(수정 없음)`·`일부 반영`·`실패`. 다른 글자를 넣으면 셀이 경고 표시가 된다.

**🔴 `반영 후 확인 중` 은 `main` 까지 머지된 뒤에 적는 값이다.** 콘텐츠 파트가 QA 하는 화면이
main 이라, 머지 전에 이 값을 적으면 **그쪽이 아직 없는 것을 보러 간다.**

| 지금 상태 | J 에 적을 값 |
|---|---|
| 고쳤지만 아직 PR 안 냄 / 리뷰·머지 대기 | **`수정 중`** |
| **main 까지 머지 완료**, 화면은 내 눈으로 못 봄 | `반영 후 확인 중` |
| main 머지 + 스모크 통과 또는 내 눈으로 확인 | `반영 완료` |

- 머지했어도 **내 눈으로 화면을 확인하지 못했으면 `반영 후 확인 중`** 이다. 함부로 `반영 완료` 로 적지 않는다.
- **K(메모)는 콘텐츠 파트와 같이 쓰는 칸**이다 — 그쪽이 '확인 완료' 를 여기 적는다.
  `memo.py` 가 덮어쓰지 않고 줄을 바꿔 이어 붙인다. 덮어쓰려면 `--replace` 를 일부러 줘야 한다.
- **L 은 건드리지 않는다.**

## 5. 마지막에 보고한다

- 스모크 결과: `통과 N · 탈락 N` 한 줄. 탈락이 남았으면 그것만 따로
- 확인만 한 것: 왜 손 안 댔는지
- **물어야 하는 것(C)**: `docs/DECISIONS.md` 에 쌓은 블록을 제목만 나열한다. 선택지는 파일에 있다
